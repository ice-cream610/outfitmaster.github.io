# MVP验收路径

> 当前验收以 [需求纠偏记录](correction-2026-10-14.md) 的角色、材质和真实商品标准为准。二维纸娃娃方案已撤下，不能因为以下功能测试通过就宣称视觉达标。

## 本地运行

Node.js 24或更高；依赖已安装时执行 `npm run dev`。前端默认5176、后端8787。生产预览：`npm run build` 然后 `npm start`，访问8787。无密钥时使用清楚标注的离线解析器。

## 完整演示

1. 商城中搜索商品，进入详情并切换同一商品的多张图。
2. 修改“搭配偏好”的4种场景、5种风格和待购预算。
3. 点击“用这件搭一套”，检查入口商品固定、最多3套组合和卡通形象。
4. 切换方案，再说“只换裤子”，确认其他单品ID保持。
5. 输入“预算改成1元”，确认报错但保留原商品和形象；再改回900元。
6. 查看执行记录，展开偏好、候选、评分和校验。
7. 在详情记录“喜欢”或“模拟已购”，查看偏好档案变化。
8. 收藏、恢复、切换长短发；商品保持一致。
9. 勾选待购、选择尺码、模拟加购；改购买勾选不改变形象。
10. 切换无历史用户，检查均衡先验；切换公开样本，检查抠图和来源说明。

## 自动验证

- `npm test`：原版规则回归＋新工作流＋本地HTTP/SQLite集成。
- `npm run build`：严格TypeScript检查和生产构建，复制全部公开素材。
- 可选 `node scripts/verify-browser.mjs <playwright/index.mjs的绝对路径>`：使用已安装Edge无头浏览器验证商城、多方案、局部替换、预算恢复、执行记录、模拟加购、收藏、手机布局、冷启动和原版。

接口测试使用内存SQLite，不污染演示数据库。浏览器验证会在本地演示库增加少量明确标注的模拟行为和会话；可通过更换 `OUTFIT_DB_PATH` 使用独立测试数据库。`.runtime/`、`.qa/`和`.env`均不进入Git。

## 验收边界

能运行的核心是固定工作流、整套规则排序、卡通二维合成与模拟电商闭环。真实模型接口已实现但需要自行配置凭证；没有凭证时不能宣称任意自然语言已实测。服饰图片为受控商品素材，未实现任意上传图片识别或真实虚拟试穿。当前可复现而非照片级，复杂叠穿仍需进一步处理。
