# Outfit Master · AI 穿搭工作台

一个可以独立开发、构建和部署的 React + TypeScript 前端项目。以「商品 → 搭配 → 局部调整 → 购买选择」验证产品交互，当前没有后端，也没有模型或交易 API。

## 启动

建议使用 Node.js 24（版本记录在 `.nvmrc`；测试使用 Node 原生 TypeScript 支持）。

```sh
npm ci
npm run dev
```

浏览器打开终端中的地址，默认 `http://127.0.0.1:5176/`。关闭服务：在终端按 Ctrl+C。

```sh
npm test
npm run build
npm run preview
```

`dist/` 是完整静态站点。请通过 HTTP 预览，不能直接双击 HTML。资源采用相对路径，支持部署在网站子目录；不依赖个人网站运行。

开发预览使用 Vite，生产构建使用显式 esbuild 脚本（`scripts/build.mjs`），先通过 TypeScript 检查，再输出带内容哈希的脚本、样式与素材。

## 已实现

- 原型 V2 三栏：商品、形象、对话；手机端为纵向布局。
- 商品详情、来源筛选、预算校验、场景/风格条件。
- 入口商品默认锁定，替换锁定项前需确认；单件替换保留其他商品。
- 购买勾选与穿搭相互独立；替换后清除该件的勾选，所有规格在版本切换后重新确认。
- 生成中的上一版、原子切换、失败保留、重试、取消与防止旧任务覆盖。
- 四种形象、四套风格与 18 个有完整效果图的精选搭配；替换、形象切换和历史恢复均校验效果图映射，不开放缺图组合。
- 方案浏览、撤销、本浏览器收藏与关联对话恢复。
- 规格/数量/库存校验、模拟加购与订单交接；不产生真实订单。
- 本地事件记录（最近 100 条）、对话示例及有限关键词识别。

## 清楚区分：演示与真实产品

素材、商品、价格、库存和 AI 回复都是示例。货盘共有 18 件样例，其中 17 件可售；缺货样例仅保留用于验证服务端防御规则，不进入推荐候选。新增外套、内搭、裤裙与鞋履，可体验复古日常、知性通勤、温柔学院、活力街头四套完整效果。不是 PRD 规划的 60–100 件真实货盘。未实现识别、任意自然语言理解、实时生图、用户账户、后台、订单/支付、社区或跨设备同步。卡通形象不代表真人试穿或合身程度。

V2 设计的**待购预算**不计入已购衣物，与 v0.1 PRD 的整套预算有差别；这是本次演示明确采用的口径，接真实服务前需要统一产品约定。

## 更新个人网站：只维护这一份 Demo 源码

1. 在本目录修改、测试并运行 `npm run build`。
2. 运行 `node scripts/sync-portfolio.mjs ../hanxin-portfolio`，把构建结果放入个人网站的 `public/outfit-demo/`。
3. 在个人网站运行构建，发布其 **完整 `out/` 内容**。若个人网站使用单独的静态发布仓库，可更新其中的 **`outfit-demo/` 子目录**；本项目源码仓库不提交 `dist/`。
4. 不要把 Demo 的 `index.html` 放在个人网站仓库根目录，否则会覆盖个人网站首页。

此步骤只适用于已有的配套个人网站，不是独立运行的前提。同步脚本会核对目标项目名称；两个项目默认作为同级文件夹摆放。

## 单独放进 GitHub

新建项目仓库后，把本文件夹内容加入仓库（保留 `package-lock.json`），不上传 `node_modules` 或 `.env`。构建产物为 `dist/`，可部署到任意静态站点。个人网站中的「返回作品集」只在 `/outfit-demo/` 集成路径下启用；独立运行会提示当前为独立模式。

具体操作见 [GitHub 上传与部署指南](docs/github-upload.md)。仓库已包含自动测试和构建检查，尚未配置自动发布。上传时保留 `.github/`、`.gitignore`、`.gitattributes` 和 `.nvmrc` 等以点开头的文件。

本项目未包含模型密钥。未来接入模型时，通过后端接口调用；当前静态站点不能承担密钥保存、服务端价格校验与真实交易职责。
