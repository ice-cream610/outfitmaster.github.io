## 资产与提示词

- 数据：`data/editorial-catalog.json`，包含单品描述、价格、参考编号、系列和逐件替换关系。
- 商品生成提示词：`prompts.json` 的 `products`；该文件也保留最初的六格形象方案供追溯。
- 实际最终搭配提示词：`outfit-prompts-v2.json`。用户提出“更多穿搭、少做同款形象”后，后 8 组改为四格不同服饰组合。
- 首页抠图：`hero-prompt.txt` → `public/editorial/hero.png`。
- 所有视觉生成均使用内置 imagegen。`orchid` 首次网络失败后重试成功；没有使用 CLI 回退。
- 前四张图集是 3 列 × 2 行，后八张是 2 列 × 2 行，单格均为正方形。代码按完整商品 ID 集合和形象匹配，无对应图不允许当作成功试穿。
- 已人工查看 12 张图集、53 张商品图的检视页和首页抠图，核对主要色彩、款式、组合和全身构图。AI 重建仍有纹理、配饰五金及局部衣褶差异，属于造型示意，不是原商品的精确扫描或合身预测。

## 页面和流程

- 整站视觉统一为电光蓝、莓果粉、柠檬黄与浅紫的多巴胺风格，覆盖商城、搭配列表、详情、工作台、弹窗与反馈状态。视觉层在 `src/curated/dopamine.css`，不改变点击流程、路由或筛选行为。
- 删除商城公共页脚。原来 900px 导航换行和 600px 商城纵向布局继续沿用；套装详情在窄屏使用可收缩网格与正方形展示，避免大图撑宽页面。
- 导航统一为「精选搭配」；先展示复古、礼服、都市、甜美等不同方向。
- 商品呈现与快速体验保持 4:6；换用新单品及透明 E 形象。
- 工作台在 1146px 视口的三列实测约 264 / 588 / 250px；中间舞台加宽。825px 使用窄左栏＋宽舞台、对话下移；窄手机纵向排列。
- 待购预算为可选数字输入，空值使用 `null`，筛选时视为不限额。没有把 Infinity 序列化到接口；负数和非有限值被拒绝。删除原预算下的多余说明。
- 新增连衣裙、帽饰、包袋类别；双层内搭逐件匹配，避免替错内外层。
- 单件替换维持当前形象；整套换风格允许使用新系列对应的 E 形象。历史恢复、选购、锁定和完整组合校验继续生效。
- AI 接口保持两阶段流程；新增品类及可选预算贯穿校验。用 sharp 在服务器中制作 640px JPEG 传输副本，原商品图不变；避免一次发送几十张大 PNG。
