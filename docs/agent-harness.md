# 穿搭 Agent：实现与学习地图

本版采用固定工作流，没有无限的自主工具循环。真实模型配置后负责自然语言需求解析；组合搜索、评分、校验和图层呈现由可检查的代码执行。未配置密钥时明确显示离线模式。

## 从一次调用开始阅读

1. `src/mvp/App.tsx` 的 `start()` / `send()` 收集入口商品、标签和对话。
2. `src/mvp/service.ts` 的 `recommend()` 调用后端；仅前端预览时使用同一份本地工作流。
3. `server/index.mjs` 检查会话归属和版本，从数据库恢复可信状态。
4. `src/agent/workflow.ts` 的 `runWorkflow()` 按以下顺序执行：
   - 接收输入：商品 ID 关联该商品多张图及属性。
   - 推断偏好：读取模拟购买、收藏、浏览和负反馈，按权重与时间衰减归一化。
   - 解析需求：真实模型或明确标注的有限离线解析器返回修改字段。
   - 检索候选：库存、禁用项、锁定项及局部保留范围。
   - 搜索组合：基础模板，上衣＋下装＋鞋，或连衣裙＋鞋；外套和包可作为保留项。
   - 整套评分：颜色21%、风格17%、场景18%、比例10%、图案8%、偏好21%、价格余量5%。
   - 校验：商品真实性、完整结构、预算、锁定、重复与库存。
   - 输出：最多3套差异方案、理由、明细和执行记录。
5. `src/mvp/Avatar.tsx` 将相同服饰素材按固定图层和位置呈现。

权重在 `data/styling-knowledge.json`，属于待验证的设计假设，不是行业标准或经过训练的购买概率。候选宽度上限约30、束宽160，有界搜索无法证明全局最优或严格无解。每一步记录真实中间数据，不依靠模型自述推理来判断是否正确。

## 六个 harness 组成

|组成|实现位置|你可以先修改什么|
|---|---|---|
|提示与上下文|`server/prompts/intent.md`、`server/model.mjs`|增加需求表达示例，检查字段是否准确|
|流程控制|`runWorkflow()`|观察条件冲突在何时停止，调整有限重试|
|工具与规则|`validateOutfit()`、候选过滤和组合搜索|增加品类规则，不将预算交给模型估计|
|会话状态|`SessionState`、SQLite sessions|检查版本、锁定项和局部修改范围|
|运行记录|`TraceStep`、前端执行记录弹窗|查看实际候选、评分与失败位置|
|评测|`tests/workflow.test.mjs`、`tests/api.test.mjs`|先加入失败样例，再修改规则并回归|

## 一个适合一起完成的小实验

选择 `studio-0-1`，先看3套结果，再依次输入：

- “只换裤子”：记录上衣和鞋 ID 是否保持，下装是否改变。
- “不要裙子”：记录排除字段，而不是仅看回复文字。
- “预算改成1元”：应返回冲突，不能改入口商品或显示新图。
- “预算改成900元”：应恢复推荐，不能因上一次失败毁掉有效会话。

随后仅修改颜色与偏好权重，使用同一用户和商品比较排序。固定测试只能保证规则正确；审美质量仍应让用户评价，并记录“愿意穿”“愿意购买”及原因，不能用自己的分数验证自己。

## 真实模型配置

复制 `.env.example` 为 `.env`，配置 `MODEL_API_KEY`、`MODEL_BASE_URL` 和 `MODEL_NAME`。模型服务使用兼容的 Chat Completions JSON 输出接口，可配置千问或 DeepSeek。JSON Mode 不保证业务正确，`validatePatch()` 仍验证字段和类型。最多尝试2次，每次25秒，401/403/429直接返回错误，失败不静默冒充模型成功。

首轮推荐无需调用语言模型：标签和已整理商品足以驱动确定性评分。后续自由表达才触发需求解析。此版本没有视觉大模型自动识别任意照片、模型训练、真实支付、登录鉴权或多商户运营能力。演示用户可切换，不属于隐私账号隔离产品；服务仅监听本机。

## 图像方案的边界

OCR识别的是文字，本版使用透明素材和白底连通区域抠图。商品库的30张公开商品主图缓存为PNG，60件原创矢量素材原生透明；详情页保留同一商品的其他图片。抠图适合清晰商品平拍图，浅色服装可能被误删、复杂背景无法准确分割。

显示是固定姿态的二维纸娃娃式合成，颜色和纹理不会被随机重绘。外部服饰按槽位缩放，尚无服装网格变形、姿态适配、遮挡分割或布料模拟。它提供可复现搭配示意，不能当成真实试穿。之后若升级，先加入人工锚点和分片变形，再评估专用分割；卡通风格继续保留。

## 下一轮最有价值的优化

1. 纠正公开商品的粗属性标签，提高输入质量。
2. 增加季节、温度和材质信息；当前未做天气推断。
3. 收集成套人工偏好评审，校准权重而不是持续堆规则。
4. 从有限搜索升级可验证的约束优化，并衡量多方案差异性。
5. 对照测试不同自然语言模型，再决定是否引入更完整的 Agent 框架。
