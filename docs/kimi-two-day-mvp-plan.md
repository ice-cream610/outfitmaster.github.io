# Outfit Master：Kimi 活动两日 MVP 计划

计划日期：2026-10-14。目标在 10 月 15 日晚前完成可提交演示，具体以活动截止时间为准。
活动信息依据用户粘贴的官方介绍：面向 27 届及以后毕业的在校生，2026 年 10 月 24 日 18:00—21:00 在北京举办；报名成功后收到邀请函。正文没有给出作品技术门槛、报名截止时间或分享规则。本计划不承诺活动入选。

活动表达强调跨越专业与岗位标签、自主探索；据此推断，作品值得突出个人观察、审美选择和跨产品/设计/工程的实践，但不能将此当作已确认的筛选评分标准。报名表具体字段尚未看到。作品目标是可亲自解释的完整实验，而非堆叠技术名词。

## 1. 作品主张

从一件商品出发，Agent 在有限货盘内理解场景、偏好与待购预算，调用商品工具，推荐整套搭配；支持锁定、单件修改、解释和模拟加购。

最值得展示的是自然语言需求如何变成可执行、可验证的购物决策。E 形象承担呈现与记忆点；电商增购属于待验证的业务假设。

## 2. 现状与复用

- React + TypeScript 前端、商品详情弹层、锁定、替换、撤销、收藏、购买规格校验和模拟交接已经存在。
- 18 件演示商品（17 件可售）、四种形象与 18 个登记的形象组合。
- 没有后端和模型 API；对话为有限关键词逻辑。
- 当前推荐、替换、恢复均受预置效果图映射限制。接 Agent 前必须将商品有效性与图片可用性解耦。
- 现有商品图、价格和库存是演示数据，不能对外称为真实商家货盘。

## 3. 两日必做范围

| 模块 | 实现程度 | 验收 |
|---|---|---|
| 模拟店铺 | 商品列表、筛选、详情、帮我搭配入口 | 从任意支持商品进入，入口商品锁定 |
| 推荐 Agent | 服务端真实调用模型，循环调用受控商品工具 | 非预置表述也能解析；工具返回实际影响结果 |
| 推荐规则 | 库存、预算、来源、品类、锁定、局部修改边界 | 服务端独立校验，不依赖模型自报 |
| 推荐解释 | 配色、轮廓、场景及取舍 | 引用商品属性，避免编造材质或客观审美结论 |
| 多轮调整 | 改预算、改风格、替换单件、保留单品 | 继承条件，明确用户更新的条件；不擅自解锁 |
| 可视化 | 已匹配组合使用 E 预置图；其他组合商品拼搭 | 不显示不对应的旧图；清楚标注预置/拼搭 |
| 电商闭环 | 勾选规格、模拟购物车、继续搭配 | 勾选只影响购买，已有服饰不重复购买 |
| 过程记录 | 请求 ID、工具调用、约束校验、耗时、模型用量（接口提供时） | 可查看脱敏执行记录；不展示内部思维链 |
| 作品交付 | 可访问演示、源码、README、演示录像、简短架构与评估 | 入口清晰，真实与模拟能力标明 |

不安排：实时三维模型、社区、账号体系、真实支付、真实平台对接、模型训练、复杂衣橱、向量数据库。实时图片生成仅在核心闭环完成后按实测决定。

## 4. Agent 实现

采用单 Agent + 有限工具循环，复用前端并新增轻量服务端，不搭建多 Agent 系统。

1. 服务端从可信商品数据及会话版本恢复入口、锁定、已有衣物与当前条件。
2. 模型解析本轮目标；必要时调用条件更新工具。不明确且影响结果时询问。
3. `search_products`：按品类、来源、可售状态等取候选，返回商品 ID 和可信属性。
4. 模型基于配色、轮廓、风格及场景组合候选；初期只返回 1—2 套方案。
5. `validate_outfit`：检查商品 ID、品类槽位、库存、来源、价格、预算、锁定项、局部修改范围。
6. 校验失败时返回具体原因，允许有限轮次修正；超过上限或无解时保留原方案并说明冲突。
7. 成功后建立新搭配版本；商品、说明和视觉状态一起更新。
8. 用户主动选择商品并确认规格后，才写入模拟购物车；Agent 不自动下单。

约定：待购预算覆盖搭配中所有未拥有商品，与用户最后勾选的购物车金额分开。规则是硬约束；审美是解释性建议，不能用任意分数包装成客观结论。

服务端保管 API 密钥；设置调用超时、最大工具轮次、请求限流与费用限制。模型连接失败时明确显示错误或切换标明的离线演示，不伪装为 AI 成功。

## 5. 需要用户准备的外部条件

- 开通一个可用的文本模型 API，优先评估 Kimi；接入时先查官方文档确认当前模型和工具调用接口。
- 用户负责账户注册、充值和密钥创建，密钥写入服务端本地环境配置，不发聊天、不提交仓库。
- 图像 API 暂时无需开通。
- 如报名表有额外字段或截止时间，补充对应要求；提供可用托管账号以部署前后端。
- 明确 API 费用上限。先小规模联调，费用随实测记录，不预先承诺固定成本。

## 7. 演示与评估

推荐 3 分钟演示：店铺选择皮衣 → 帮我搭配 → 提出场景/预算 → 查看工具执行与商品依据 → 保留皮衣、局部替换 → 降预算或提出冲突条件 → 查看有效调整或无解说明 → 勾选规格模拟加购。

预算数字和商品选择以开发后的货盘实算确定，避免硬写不能完成的脚本。

固定验收集建议 15—20 条，覆盖首次推荐、非关键词改写、多轮继承、局部替换、锁定冲突、低预算、缺货、伪造 ID、不可用 API、无对应效果图、购买勾选和金额。

报告实际结果：硬约束通过数/用例数、调用耗时中位数与高分位数（附样本数）、重试次数、Token/用量（可获取时）；审美评价由用户或试用者单独记录，不由模型自评。不能从模拟点击宣称转化提升。

## 8. 报名材料定位

项目描述：Outfit Master 是一个面向服饰电商的可视化穿搭 Agent，将用户对单件商品的兴趣转化为整套搭配方案，并通过可验证的商品工具、多轮约束调整和模拟购物流程完成推荐闭环。

材料重点：发现的问题、Agent 与普通聊天的区别、执行证据、约束与失败处理、真实/模拟边界、当前评估结果、下一步商业验证。用户需要亲自走完演示并能解释关键设计取舍；AI 协助实现的过程如实说明。

个人叙事可从「多年观察到好看来自整体搭配，而消费者通常只买单件」出发，连接到卡通 IP 与真实衣料质感的审美选择，以及围绕真实约束构建 Agent 的工程实践。引用个人实际经历，不编造用户研究或商业效果。
